# ПР04 — параметры движения

Рабочая ветка: `pr04`. Основные файлы: `src/patrol/patrol/patrol.py`,
`parameters.py`, `controller.py`. ПР03 сохранена в своей ветке.

## Параметры

| Имя | По умолчанию | Диапазон |
| --- | --- | --- |
| linear_speed | 0.5 | 0–1 |
| turn_rate | 0.3 | −1–1 |
| publish_hz | 10.0 | 1–30 |

Все значения должны быть конечными. Указывайте числа с точкой, например `5.0`.
Проверка всей заявки выполняется до изменения активного состояния.
После успешного изменения частоты старый таймер уничтожается, новый получает
период `1 / publish_hz`. Изменение скоростей не пересоздаёт таймер.
До первой позы публикуется нулевая команда.

## Подготовка

```bash
cd ~/robotics_ws
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=16
colcon build --symlink-install --packages-select turtle_bringup patrol
source install/setup.bash
(cd src/patrol && python3 -m pytest test)
```

## Запуск

В каждом новом терминале:

```bash
cd ~/robotics_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=16
```

Терминал A:

```bash
ros2 launch turtle_bringup sim.launch.py
```

Терминал B:

```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
```

Терминал C:

```bash
ros2 param list /patrol
ros2 param get /patrol publish_hz
timeout --signal=INT 10s ros2 topic hz /turtle1/cmd_vel
ros2 param set /patrol linear_speed 0.8
ros2 param set /patrol turn_rate -0.5
ros2 topic echo /turtle1/cmd_vel --once
ros2 param set /patrol publish_hz 5.0
timeout --signal=INT 10s ros2 topic hz /turtle1/cmd_vel
ros2 param set /patrol publish_hz 0.0
ros2 param get /patrol publish_hz
timeout --signal=INT 10s ros2 topic hz /turtle1/cmd_vel
ros2 service call /clear std_srvs/srv/Empty '{}'
ros2 action list -t
```

Поток сначала около 10 Гц, затем около 5 Гц. Ноль отклоняется с причиной,
значение остаётся 5.0, поток продолжает идти на 5 Гц. `timeout` завершает
измерение с кодом 124 — это ожидаемо. После показа остановите B и A через Ctrl+C.

Запрос сервиса `/clear` выполняет короткую операцию и возвращает один ответ.
Цель действия `/turtle1/rotate_absolute` описывает длительную операцию,
для которой возможны обратная связь, результат и отмена.

## Дефект

В отдельной ветке `pr04-defect` отключена проверка запрашиваемой частоты.
Та же команда `ros2 param set /patrol publish_hz 0.0` приводит к
`ZeroDivisionError` при пересоздании таймера. Реальный traceback и команды
сохранены в `evidence/pr04/defect-node.txt` и `defect-cli.txt`.
В исправленной ветке заявка отвергается до изменения состояния.

Для автоматического повторения всех опытов (без окна turtlesim):

```bash
python3 tools/check_pr04_runtime.py
```

Скрипт использует отдельный ROS_DOMAIN_ID=116, запускает собственные процессы,
закрывает их после проверки и перезаписывает только evidence/pr04 с выводами.
Для опыта с дефектом нужна локальная ветка `pr04-defect`.

## Отчёт и course kit

Официальный kit должен содержать `practices/manifests/pr04.json`.
Установленный ранее v1-w03 содержит только ПР01–ПР03.
После коммита реализации команда ниже получает kit с сайта курса,
проверяет SHA256 архива и файлов, обновляет report.json и запускает checker:

```bash
python3 tools/prepare_pr04_report.py
```

Если сайт недоступен, команда завершится с объяснением и не заменит отчёт.
Можно скачать архив и его SHA256 со страницы course kit самостоятельно и передать:

```bash
python3 tools/prepare_pr04_report.py \
  --archive /путь/к/официальному.tar.gz \
  --url 'https://ros.lms.ci.nsu.ru/downloads/точное-имя-архива.tar.gz' \
  --sha256 'точная-контрольная-сумма-с-сайта'
```

До успешной проверки отчёт является черновиком: в нём явно отмечен
пропуск официального контракта. Код, функциональные тесты и живые опыты
проверены независимо от доступности сайта.
